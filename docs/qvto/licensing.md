# Licensing

The QVTo engine is licensed under the Eclipse Public License 2.0, like SimOxide and like Eclipse
QVTo and Eclipse OCL, whose semantics it follows. One part is kept apart: the emulation of Java's
`HashMap` order and of HotSpot's identity hashes. Only OpenJDK's and HotSpot's sources define
these, so they live in an opt-in crate for which no licence is granted. Only compat mode needs
them. The repository's `LICENSES` file is the authoritative text; this page summarises the parts
that concern the engine.

## Modes and builds

| Build | Modes | Contains | May be distributed |
|---|---|---|---|
| default (`cargo build -p qvto-cli`, any crate without features) | fast, ordered | EPL-2.0 code only | yes |
| feature `compat` (`qvto-runtime`, `qvto-vm`, `qvto`, `qvto-testkit`, `qvto-cli`; in SimOxide `simoxide-reconf`'s `compat`, or `exact` of `simoxide-reconf`, `simoxide-cli` and the other crates that have it) | compat, fast, ordered | also `simoxide-jcompat-exact` | **no**: no licence covers such builds (`LICENSES`, section 7) |

- **Fast and ordered mode are EPL-only.** They iterate sets, bags and dictionaries in insertion
  order. The javadoc specifies that order for `LinkedHashMap` and `LinkedHashSet`, so it needs no
  OpenJDK internals. Ordered mode reproduces both references that SimOxide compares with: the
  Slingshot reference runner's `det` mode and the patched SimuLizar reference (patch P10).
  SimOxide's reconfiguration rules therefore need no opt-in crate.
- **Compat mode** needs `java.util.HashMap`'s bucket order (hash spreading, power-of-two tables,
  resize split, constructor sizing, tree bins, removal) and HotSpot's identity-hash generator.
  They are in `crates/foundation/simoxide-jcompat-exact`. That code was written from the
  documented algorithms, black-box tests and differential tests against JDK 21, not copied from
  the sources. But the details are defined only by GPL-licensed sources, while the crates that
  use them are EPL-2.0. The crate therefore has no licence (`LICENSE-NOTICE`, no `license` in its
  manifest, `publish = false`), and builds that include it are for local use only.
- **No silent fallback.** Without the feature, compat mode is not compiled. Asking for it fails:
  `Mode::Compat.available()` is false, a run ends with the code `MODE_UNAVAILABLE`,
  `qvto conform --engine qvto` and `qvto fuzz` refuse with a message, and SimOxide's host returns
  `ReconfError::ModeUnavailable`.
- **Defaults are EPL.** Every crate's default features leave the opt-in crate out, the command
  line tools included. Tests turn `compat` on through their dev-dependencies, which does not
  change what the libraries and binaries contain.

The release check, also in [Contributing](../development/contributing.md#releases):

```sh
cargo tree -e normal -p qvto-cli        # default features; likewise -p simoxide-cli
```

must list neither `simoxide-jcompat-exact` nor `simoxide-hotspot-math`. The engine never uses
`simoxide-hotspot-math`, SimOxide's GPL-2.0-only crate for bit-exact `Math.log` and `Math.exp`.
